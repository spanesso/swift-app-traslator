## Summary

Fix the `SFSpeechRecognizer` session-timeout freeze by implementing automatic recognition restart inside `ContinuousSpeechListener` (no stream interruption, no ViewModel change). Then add SwiftData-backed conversation persistence (save, list, detail), and a `ShareLink`-based export action — all wired through a new navigation layer around the existing `LiveTranscriptionView`.

## Implementation Work Items

### Work Item 1 — Fix Pipeline Freeze (ContinuousSpeechListener)
**Priority**: P1 (blocking — everything else depends on a working pipeline)  
**File**: `TranslatorApp/Data/ContinuousSpeechListener.swift`

**What to change**:

Add a `restartRecognition(sessionId:)` private method:
```
private func restartRecognition(sessionId: String) {
    recognitionTask?.cancel()
    recognitionTask = nil
    recognitionRequest?.endAudio()
    recognitionRequest = nil
    audioEngine.inputNode.removeTap(onBus: 0)
    // do NOT call audioEngine.stop() — engine keeps running
    try? setupRecognition(sessionId: sessionId)  // re-installs tap + new task
}
```

Modify the recognition callback in `setupRecognition`:
```
// Current code:
if error != nil {
    await self.handleError()
}

// Replace with:
if result?.isFinal == true || error != nil {
    if await self.isFinished {
        // user-initiated stop: leave stream closed
    } else {
        // system-initiated end (timeout): restart transparently
        await self.restartRecognition(sessionId: sessionId)
    }
}
```

**Why `result?.isFinal` matters**: Apple's recognizer signals timeout via both `isFinal = true` in the result AND an error. Checking `isFinal` catches the timeout case cleanly even if the error parameter varies by OS version.

**Threading note**: The recognition callback is called on an internal `SFSpeechRecognizer` queue. The `Task { ... }` wrapper already moves execution into the actor; `restartRecognition` is an actor method and runs serially.

### Work Item 6 — SaveConversationUseCase (Domain)
**Priority**: P2  
**File**: `TranslatorApp/Domain/UseCases/SaveConversationUseCase.swift` (NEW, ~40 lines)

```swift
final class SaveConversationUseCase {
    private let repository: ConversationRepositoryProtocol
    func execute(englishText: String, spanishText: String) async throws {
        guard !englishText.trimmingCharacters(in: .whitespaces).isEmpty else {
            throw ConversationError.emptyTranscript
        }
        let entity = ConversationEntity(id: UUID(), englishText: englishText,
                                        spanishText: spanishText, savedAt: Date())
        try await repository.save(entity)
    }
}
```

Add `ConversationError` enum in the same file (or a shared `SpeechError`-adjacent file): `case emptyTranscript`.

### Work Item 9 — ConversationHistoryViewModel (new)
**Priority**: P2  
**File**: `TranslatorApp/Presentation/ViewModels/ConversationHistoryViewModel.swift` (NEW, ~80 lines)

```swift
@MainActor
@Observable
final class ConversationHistoryViewModel {
    var conversations: [ConversationEntity] = []
    var isLoading: Bool = false
    var errorMessage: String? = nil

    private let fetchUseCase: FetchConversationsUseCase

    func loadConversations() async {
        isLoading = true
        defer { isLoading = false }
        do {
            conversations = try await fetchUseCase.execute()
        } catch {
            errorMessage = "Could not load conversations: \(error.localizedDescription)"
        }
    }
}
```

## Risk Register

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| `SFSpeechRecognizer` restart delay causes a gap in transcription | Medium | Restart is fast (<100ms); NLP segmenter's silence timer covers natural pauses; no user-visible gap expected |
| SwiftData `ModelContext` thread safety (main context on background thread) | Low | `ConversationRepository` operations are called from MainActor (ViewModel) → main context is safe |
| `restartRecognition` called while previous task cleanup is still async | Low | Actor serialization ensures only one call runs at a time; `isFinished` guard prevents spurious restarts |
| `LiveTranscriptionView` exceeds 250-line limit after additions | Medium | Extract Save/Export button group into a private `SessionActionsView` sub-component if needed |
| `NavigationStack` around full-screen dark view causes unwanted chrome | Low | `.navigationBarHidden(true)` or `.toolbar(.hidden)` on `LiveTranscriptionView` |
